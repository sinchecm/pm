# Frontend

Next.js 16 (App Router), React 19, TypeScript, Tailwind v4, dnd-kit. Built as a static export (`output: "export"` -> `out/`) that FastAPI serves at `/` inside the Docker image. Users sign in or register, then work with any number of boards loaded from and saved to the backend API.

## Structure

- `src/app/layout.tsx` - root layout; loads Space Grotesk (`--font-display`) and Manrope (`--font-body`) via `next/font/google`.
- `src/app/page.tsx` - client component; on load calls `GET /api/me`. A 401 shows `AuthForm`; any other failure shows a "Could not reach the server" error; otherwise renders `Workspace`. Handles logout (`POST /api/logout`) and `onSignedOut(message)` (session expired, account deleted), which returns to the form with a notice.
- `src/lib/api.ts` - `request(url, method, body)`: JSON fetch wrapper that rejects with `ApiError` (has `status`) on non-2xx and returns `undefined` for 204. `send()` is the same but resolves with the `Response` (for headers) and takes extra headers. `fetchBoard(id)` returns `{ data, etag }`. `isUnauthorized(error)` / `hasStatus(error, status)` check the status.
- `src/components/AuthForm.tsx` - sign in / create account form (toggle) posting to `/api/login` or `/api/register`; reports the returned user via `onAuthenticated`. Errors: invalid credentials, username taken (409), invalid details (422), server unreachable. Takes an optional `notice`.
- `src/components/Workspace.tsx` - signed-in shell: top bar (username, Account, Log out), a "Boards" `nav` (select, New board form) and the main area. Loads `GET /api/boards`, then the selected board's data and ETag, members and comment counts in parallel; a "My cards" entry above the boards opens `MyCards`; shared boards show "Shared by <owner>"; the selected board id is kept in the URL hash (`#board-3`, via `history.replaceState`). Creates (`POST`), renames (`PATCH`, from the board header) and deletes (`DELETE`, after `confirm`) boards, then selects the next one or shows "No boards yet". Renders `KanbanBoard` keyed by board id (state and chat reset when switching) with the user's `role`, or `AccountSettings`. Leaving a shared board removes it from the list. Any 401 calls `onSignedOut`. Callbacks passed down are memoized (and `page.tsx`'s `onSignedOut` is stable) so child effects such as the members fetch don't re-run on every render.
- `src/components/BoardMembers.tsx` - controlled members panel (`members`, `onMembersChange`); calls `onMemberRemoved` after a removal because the server unassigns that member's cards (new board version). Owners add members by username ("Add member"; 404/409 explained) and remove them; members see a "Leave board" button for themselves (after `confirm`), which calls `onLeave`.
- `src/components/MyCards.tsx` - "My cards" view (`GET /api/me/cards`): open cards assigned to the user across boards with board, column, priority and due date; "Open board" calls `onOpenBoard`.
- `src/components/CardComments.tsx` - comments panel inside a card (loads on open; post; delete for the author or the board owner). Reports the new count with `onCountChange`. `CommentsContext` bundles the board-level props it needs.
- `src/components/AccountSettings.tsx` - change password (`PUT /api/me/password`) and delete account (`DELETE /api/me` with password, after `confirm`).
- `src/app/globals.css` - Tailwind import plus CSS variables for the project color scheme (`--accent-yellow`, `--primary-blue`, `--secondary-purple`, `--navy-dark`, `--gray-text`) and surface/stroke/shadow tokens. Components reference these as `text-[var(--navy-dark)]` etc.
- `src/lib/kanban.ts` - data model and pure logic:
  - Types: `BoardData = { columns: Column[]; cards: Record<string, Card> }`, `Column` holds ordered `cardIds`, `Card` is `{ id, title, details, priority, dueDate, labels, checklist }` (`priority` is `"low" | "medium" | "high" | null`, `dueDate` is `YYYY-MM-DD` or null, `checklist` items are `{ id, text, done }`). Also `BoardSummary` (with `owner`, `role`), `Member`, `Role`, `User`, `CardFilter` (`query`, `priority`, `label`).
  - `initialData` - the default board (same as `backend/app/default_board.json`); only used by tests.
  - `moveCard(columns, activeId, overId)` - reorders within a column or moves across columns. Dropping on a column id appends; dropping on a card id inserts at that card's position.
  - `matchesFilter(card, filter)` (search text in title/details/labels, priority, label), `parseLabels(text)` (comma separated, trimmed, unique, max 30 chars), `parseChecklist(text, existing)` (one item per line; lines matching an existing item keep its id and tick, each item at most once), `boardLabels(board)`, `isOverdue(card, today)`, `boardStats(board, today)` (total, open high priority, overdue; the last column counts as done), `todayIso()`, `formatDueDate()`, `createId(prefix)`.
- `src/components/KanbanBoard.tsx` - takes `boardId`, `name`, `initialBoard`, `initialEtag`, `initialMembers`, `initialCommentCounts`, `role`, `username`, `onRename`, `onDelete`, `onLeave`, `onSessionExpired`; owns board state (`useState`). Header: board name (editable by the owner, commits on blur/Enter; read-only for members), stats line, AI Assistant / Add column / Share (owner) or Members / Delete board (owner only) buttons, the toggleable `BoardMembers` panel (opening it refreshes the members, which also feed the assignee options), an assignee filter (when there are several members), search, priority filter and label filter (shown when any card has labels). An effect saves every change with `PUT /api/boards/{id}` through `queueSave`, queued so saves reach the server in order, each with `If-Match` set to the last known ETag (from the initial load, the previous save, or a board returned by the AI). After a member is removed the latest board is loaded. A 412 means someone else changed the board: queued saves from the stale board are dropped (a generation counter), the latest board is loaded, and a notice explains the last change was not saved. The queue survives failures: a 401 calls `onSessionExpired`, other failures show a "could not be saved" notice with Retry (each save sends the whole board, so the next success covers earlier failures). `savedBoard` tracks what the server already has, so boards returned by the AI (already saved by the chat endpoint) are applied without a second save. While the AI is working the board area is `inert`. When the chat is open the board gets right padding so the sidebar doesn't cover it. Owns the dnd-kit `DndContext` (PointerSensor, 6px activation distance, `closestCorners`). Handles drag end, column add/rename/delete (deleting a column with cards asks to confirm), add, edit and delete card. Columns scroll horizontally when they don't fit.
- `src/components/KanbanColumn.tsx` - droppable column (220-360px wide); title is an always-editable input; "Remove" button (`Delete column <title>`) unless it's the only column; renders the (filtered) cards in a `SortableContext` plus `NewCardForm`.
- `src/components/ChatSidebar.tsx` - fixed right-hand AI chat panel for one board (`boardId`); always mounted and hidden via `isOpen` so the conversation survives closing. Posts `{message, history}` to `/api/boards/{id}/chat`, shows "Thinking..." while waiting, reports `onPendingChange`, calls `onBoardUpdate(board, etag)` when the reply includes a board, and on any failure restores the message with an error line.
- `src/components/KanbanCard.tsx` - sortable card showing title, details, label chips, the checklist with "Checklist n/m" progress (items can be ticked directly, which saves), an assignee chip, a priority badge, a due date chip and an "n comments" button that opens `CardComments` ("Overdue: ..." when `isOverdue`), with Edit and Remove buttons. Edit switches to an inline form (title, details, priority select, due date input, assignee select from the board members, comma-separated labels, checklist one item per line); drag listeners are not attached while editing or while comments are open.
- `src/components/KanbanCardPreview.tsx` - static card used in the `DragOverlay`.
- `src/components/NewCardForm.tsx` - toggleable form to add a card (title required, details optional, defaults to "No details yet.").

## Tests

- Unit (Vitest + Testing Library, jsdom): `src/lib/kanban.test.ts` (moveCard, filters, stats, dates), `src/components/KanbanBoard.test.tsx` (UI actions and the PUT saved for each, columns, card fields, filters, stats), `Workspace.test.tsx` (board list, hash selection, create/rename/delete, shared boards, leaving, ETag, errors), `BoardMembers.test.tsx`, `MyCards.test.tsx`, `CardComments.test.tsx`, `AuthForm.test.tsx`, `AccountSettings.test.tsx`, `ChatSidebar.test.tsx`, `src/app/page.test.tsx` (sign-in flow and sign-out paths). `src/test/mockApi.ts` stubs `fetch` with a route table keyed by `"METHOD /url"` (unknown routes throw) and `requestsTo()` returns the JSON bodies sent to a route. `window.confirm` is stubbed with `vi.spyOn`. Setup in `src/test/setup.ts`; config in `vitest.config.mts`. Coverage: `npx vitest run --coverage`.
- E2E (Playwright, Chromium, 1600x1000 viewport, 2 workers because more push this machine into swap): `tests/auth.spec.ts` (demo login, register, taken username, change password, delete account), `tests/boards.spec.ts` (create/switch/rename/delete boards, hash kept on reload, users isolated), `tests/kanban.spec.ts` (add, edit, rename, drag, columns, priority/due date, labels/checklist, filters), `tests/persistence.spec.ts` (all changes survive reload and re-login), `tests/sharing.spec.ts` (two users in separate browser contexts: share, member edits, stale-edit conflict, remove, leave, assign and My cards, comments), `tests/chat.spec.ts` (real AI). `registerUser` in `tests/helpers.ts` registers a unique user per test through the API, so tests are independent and run in parallel. They run against a throwaway test container on `http://localhost:8002` started by `scripts/test-e2e.sh` (override with `BASE_URL`). Never point them at the real app on 8001.

## Commands

```bash
npm run dev
npm run build
npm run lint
npm run test:unit
../scripts/test-e2e.sh   # e2e in an isolated test container
```

`npm run dev` serves the UI without the API, so it only shows the login form; use the container for real testing.

## Conventions

- Path alias `@/` -> `src/`.
- Test selectors: `data-testid="column-<id>"`, `data-testid="card-<id>"` (so other test ids must not start with `card-`), `board-stats`, `due-date`, `checklist-progress`, `member`, `assignee`, `my-card`, `comment`, `current-user`, `board-area`, `chat-message-user|assistant`, plus aria labels ("Board name", "New board name", "Column title", "Delete column <title>", "Card title", "Card details", "Priority", "Due date", "Labels", "Checklist", "Filter by label", "Share with username", "Remove <username>", "Assignee", "Filter by assignee", "Comments on <title>", "New comment", "Delete comment by <author>", "Edit <title>", "Delete <title>", "Search cards", "Filter by priority", "Message") and the "Boards" navigation landmark.
